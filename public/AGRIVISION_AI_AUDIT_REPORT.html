2. Deep Forensic Audit of the Active ONNX Model

File: public/models/tomato_disease_mobilenetv3.onnx

We executed a direct binary and protobuf graph inspection using Python's onnx library. Here are the exact specifications:

  • File Size: 22,363 bytes (~21.8 KB)
  • Producer: AgriVision-ONNX-Engine (synthetically generated, not PyTorch)
  • Input: input_leaf_tensor [1, 3, 224, 224] (Float32)
  • Output: disease_probabilities [1, 10] (Float32)
  • Total Parameters: 5,406 parameters (A real MobileNetV3 has 2,500,000 to 5,400,000 parameters)
  • Nodes (Exactly 7 Nodes): Conv(16) → Relu → Conv(32) → Relu → GlobalAveragePool → Flatten → Gemm(10)
  • Weights: Uniform random numbers (mean ~0.002, std ~0.10). Not trained.
// What the inference engine actually does in src/services/onnx/inferenceEngine.ts:
1. Loads 22KB toy model into onnxruntime-web WASM
2. Feeds image tensor -> outputs ~0.10 for all 10 classes
3. If session fails -> falls back to hardcoded pixel-color heuristic:
   darkNecrosis = 100 - (R + G + B)/3
   yellowChlorosis = (R + G)/2 - B - 25
   greenVigor = G - max(R, B)
